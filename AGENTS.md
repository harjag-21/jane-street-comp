# Claim verification for this project

Before presenting any checkable factual claim in a response from this workspace, verify it against suitable evidence or clearly label it as unverified. Apply this to every claim, including claims repeated from earlier project discussions or documents; prior repetition is not evidence.

- For current competition rules, dates, tool behavior, standards, or other changeable facts, recheck an authoritative primary source at the time of the answer. Link the source and state when it was checked when that matters.
- For technical statements about this design, inspect the relevant source, configuration, or reproducible evidence. Point to that evidence. Do not describe planned or inferred behavior as implemented or measured.
- Classify project claims using `docs/COMPETITION_PLAN_AND_EVIDENCE.md`: official fact, prior-art observation, design hypothesis, or measured result. Preserve the distinction between simulation, gate-level evidence, and measured silicon.
- When evidence is missing, conflicting, stale, or inaccessible, say so plainly and state what is known and what remains unverified. Do not fill gaps with plausible-sounding detail.
- Cite verified external claims close to the statement. For sourced project claims, give a direct source link or workspace file/artifact reference. Mark reasoning that goes beyond the cited evidence as an inference.
- Before reusing a prior claim, check its source and date again if it could have changed. Keep the evidence ledger current when the user asks to update project claims or results.

The evidence ledger is the project-specific reference for claim status and evidence:
`docs/COMPETITION_PLAN_AND_EVIDENCE.md`.
