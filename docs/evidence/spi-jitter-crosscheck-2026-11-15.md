## Defect found and correction

The first seeded Cocotb comparison failed at a one-cycle low phase. The simulator showed a late target transition changing MISO after its intended sample and affecting a later sample. The old Python model retained the previous sampled bit indefinitely, so it predicted the wrong received byte. This was a modeling defect found by cross-checking, not a Cocotb failure.

`run_trial` now schedules all seven target transitions at absolute event times and applies them before each rising-edge sample. A missed transition remains pending and may affect later sampled bits. A transaction is classified as passing only if its byte is correct and all seven transitions meet the declared setup requirement at their intended samples. Equality passes. A regression test pins the late-transition example at `L=1`: received byte `0xD5`, with all seven intended-sample setup checks failing.

## Scope and limits

This verifies consistency between the Python event model and a Cocotb target model using the same declared timing semantics. The target is synthetic, and the Verilog top is an empty signal shell. The test's serialized target coroutine requires each delayed update to arrive before the next falling SCLK edge; the tested jitter bound satisfies that condition. The check does not establish metastability behavior, analog pad timing, competition RTL correctness, routed timing, GDS/precheck completion, or silicon behavior.
